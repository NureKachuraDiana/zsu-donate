# ZSU Donate — навчальна інтеграція WayForPay

## Налаштування
1. У https://www.wayforpay.com/ створіть власний магазин і перевірте його тестовий режим. Не активуйте бойові платежі для навчального тесту.
2. У налаштуваннях магазину знайдіть Merchant Account, Secret Key та домен магазину. У PowerShell у папці проєкту задайте їх (Node.js 18+):

```powershell
$env:WFP_MERCHANT="ваш_merchantAccount"
$env:WFP_SECRET="ваш_merchantSecretKey"
$env:WFP_DOMAIN="домен_магазину"
node server.js
```

Не надсилайте секретний ключ стороннім і не додавайте його до Git. Залежностей npm немає. Відкрийте http://localhost:3000. Для серверного callback та надійного повернення з платіжної сторінки можна використовувати публічний HTTPS URL, наприклад тунель, і задати `$env:BASE_URL="https://ваш-публічний-домен"` перед запуском; узгодьте домен із налаштуваннями магазину. Без HTTPS callback не передається, але сторінка результату запитує CHECK_STATUS після повернення браузера.

## Підтвердження для викладача
- У кабінеті магазину відкрийте Повідомлення, додайте email та активуйте потрібні сповіщення: https://help.wayforpay.com/view/3342465
- Використовуйте тільки тестові реквізити картки, підтверджені WayForPay для вашого магазину. Якщо їх немає, зверніться в підтримку. Не використовуйте реальні картки.
- Оберіть суму, введіть email, перейдіть на WayForPay і зробіть тестову спробу оплати.
- Відкрийте Транзакції власного магазину, знайдіть замовлення за orderReference та зробіть скриншот фактичного статусу. Якщо надійшов лист про успіх, збережіть його також. Наявність тестової транзакції та доставка листа залежать від режиму й налаштувань WayForPay.
- Листи надсилає WayForPay, а не сервер проєкту. Статус Approved відображається лише після перевірки підпису відповіді API або callback.

Документація: https://wiki.wayforpay.com/view/852102 та https://wiki.wayforpay.com/view/852117 .
Замовлення зберігаються в пам'яті до перезапуску; це навчальний проєкт, не production.
